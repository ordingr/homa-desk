### Findings, ranked

#### BLOCK

**R9-B1. A Mermaid `themeCSS` directive in a previewed Markdown file makes the full page fetch an arbitrary URL
(SEC-10, SEC-5, DEC 13 "nothing leaves the PC").** `web/src/preview/MermaidDiagram.jsx:17-29` initialises Mermaid with
`securityLevel: "strict"` and sanitises the SVG with DOMPurify — both correct — but Mermaid's `strict` level governs
labels and click handlers, not the stylesheet it emits. A diagram may carry an init directive
(`%%{init: {"themeCSS": "…"}}%%`) or YAML front matter (`config: themeCSS: …`); Mermaid's `sanitizeCss`
(`mermaid.core/chunk-DU6HZSFF.mjs`, `var sanitizeCss`) only checks brace balance, and its `sanitize()` only rejects
string values containing `<`, `>` or `url(data:` — a plain `url(http://…)` passes. The CSS lands in the SVG's
`<style>` (scoped to `#pv-mermaid-N`), DOMPurify keeps `<style>` by default and does not inspect CSS, and
`dangerouslySetInnerHTML` (line 61) puts it in the live document. `fill: url(http://host/x#g)` and
`background-image: url(http://host/y)` are then fetched by the browser. No CSP is sent for `/app/*`
(`assistant/server/static.py:28` sets nosniff, no-referrer and X-Frame-Options only), so nothing stops the request.

*Observed (headless Edge, exact `renderDiagram` replica, beacon on a different origin):*
```
== t1.html (as built)
OUT: mermaid: rendered; style contains url(: true; style tag count: 1
hits:  /beacon-mermaid-themecss   /beacon-mermaid-fill
== t4.html (same via YAML front matter `config: themeCSS:`)
hits:  /beacon-mermaid-frontmatter
rendered DOM: #pv-mermaid-1 .node rect{fill:url("http://<other-origin>/beacon-mermaid-fill#g")
```
*Impact:* an outbound request to a host of the file author's choosing whenever the user previews the file — a
tracking beacon (IP, time, "this person opened this file") from a product whose first promise is that nothing leaves
the PC. Because Mermaid prefixes the rules with the diagram id, the CSS cannot select the rest of the page, so the
result list is not exfiltrated; the URL can only carry what the author already put in the file. The attack input is
realistic: a `.md` received by mail or cloned from a repository and sitting in an indexed folder.

*Fix (both verified in the same harness; do both):*
1. `MermaidDiagram.jsx` — add the style-bearing keys to Mermaid's `secure` list so directives and front matter cannot
   set them: `mermaid.initialize({ …, secure: ["secure", "securityLevel", "startOnLoad", "maxTextSize",
   "suppressErrorRendering", "maxEdges", "themeCSS", "fontFamily", "altFontFamily", "themeVariables"] })`.
   Observed (`t2.html`): `beacon occurrences in rendered output: 0`, no beacon hit, diagram still drawn (`has rect:
   true`); the one `url(` left is Mermaid's own `marker-end="url(#…)"`. Add a DOMPurify `uponSanitizeElement` hook
   that drops any `<style>` whose text contains `url(` not followed by `#`, `@import`, or `expression(` — belt for
   future Mermaid versions.
2. `static.py` — send a Content-Security-Policy on every `/app/*` response. Verified policy (`t3.html`, delivered as a
   `<meta>`; the header form additionally honours `frame-ancestors`):
   `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' blob:
   data:; font-src 'self' data:; connect-src 'self'; worker-src 'self' blob:; frame-src 'self'; object-src 'none';
   base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Observed: the diagram rendered and Edge logged
   `Loading the image 'http://<other-origin>/beacon-mermaid-fill' violates … "img-src 'self' blob: data:"`; the HTML
   iframe's own meta CSP and the inherited page CSP both reported. The bundle needs: module script from `/app/assets`
   (`'self'`), inline `<style>` from Mermaid/markmap and React `style=` (`'unsafe-inline'` on `style-src`), `blob:`
   images (`ImageView`), `data:` images (HTML preview), the same-origin pdf.js worker and its `.wasm`
   (`'wasm-unsafe-eval'`), `fetch` to `/v1` and `/app/pdfjs` (`connect-src 'self'`). `about:srcdoc` frames are
   allowed by CSP regardless of `frame-src`. The bundle has no `eval`/`new Function` (grep over every chunk: 0).
Then rebuild (`scripts/build-web.ps1`) so `assistant/static/app/**` matches `web/src` (PR8), and add the beacon
page to qa's e2e so the regression is caught: render a `themeCSS: url(http://127.0.0.1:<other-port>/x)` diagram
against a listener and assert zero hits.

#### FIX-BEFORE-M4

**R9-F1. Quadratic regular expressions in the xlsx extractor let a crafted workbook pin a worker thread for minutes
to hours.** `assistant/preview/extract.py:101,104,105` — `_SI = <si\b[^>]*>(.*?)</si>`, `_ROW = <row\b[^>]*>(.*?)</row>`,
`_CELL = <c\b([^>]*?)(?:/>|>(.*?)</c>)`, all with `re.S` and a lazy `.*?`. For an opening tag with no closing tag the
engine scans to the end of the member once per opening tag, so cost is O(n²) in member size; the 50 MB unpack cap
(`_Budget`) bounds n but not n². Observed (direct `extract_xlsx` calls):
```
[sharedStrings 16 KB unclosed <si>]   0.36s     [sheet 16 KB unclosed <row>]  0.27s    [sheet 16 KB unclosed <c>]   0.51s
[sharedStrings 32 KB unclosed <si>]   1.65s     [sheet 32 KB unclosed <row>]  1.05s    [sheet 32 KB unclosed <c>]   2.04s
[sharedStrings 64 KB unclosed <si>]   6.22s     [sheet 64 KB unclosed <row>]  4.44s    [sheet 64 KB unclosed <c>]   8.28s
[sharedStrings 128 KB unclosed <si>] 22.70s     [sheet 128 KB unclosed <row>] 17.29s   [sheet 128 KB unclosed <c>]  30.97s
```
×4 per doubling: a 1 MB member is ≈25 minutes, 4 MB ≈ 7 hours, on one core, inside `run_in_threadpool`; the pane
shows "Loading preview..." and clicking away does not stop the thread. A 300 KB `.xlsx` is an ordinary attachment.
*Fix:* make the tokenisers linear — split on the closing tag with `str.split("</si>")`/`str.find` and take the text
after the last `<si` in each piece (same for `<row>`/`<c>`), or use patterns whose repeated part cannot cross a tag
boundary (`[^<]*` style, like `_W_TOKEN` and `_A_TOKEN` already do); additionally cap each XML member at a few MB
(e.g. 8 MB for `sharedStrings.xml` and the sheet; the 50 MB total stays) and stop iterating once ROW_CAP rows are
collected (today `_ROW.finditer` still has to find the 1001st match). `docx`/`pptx` are linear already (`_W_TOKEN`,
`_A_TOKEN`); the 60 MB zero-filled `document.xml` was refused in 0.00 s and a 40 MB one extracted in 0.13 s.

**R9-F2. The private-key content check can be skipped by choosing the `range=` window (SEC-3 content rule).**
`assistant/server/routes_files.py:45,146-151` — `_read_scanned` scans the window plus `SCAN_OVERLAP = 64` bytes on
each side, so a window that starts 65 or more bytes after the `-----BEGIN … PRIVATE KEY-----` line contains the key
body but not the header. Observed on a file with the header at offset 10000:
```
range=0-9999        kind=protected     range=10040-10400  kind=protected  (header inside the +64 overlap)
range=10100-10400   kind=text  keybody_in_body=True  header_in_body=False
Range: bytes=10100-10400  → 206 text/plain, key body in the response
```
Who can do it: anyone holding the bearer, i.e. the user's own page or a local process that already read the token
file — so this is a weakening of a defence-in-depth rule rather than a privilege gain, and the page's own "Show more"
flow cannot reach it (it walks forward in 1 MiB steps from 0, and the window that contains the header refuses, which
stops the walk). It still means the HTTP route is less strict than `read_text_preview` (first 1 MiB always scanned).
*Fix:* scan the file head too — `denylist.content_has_private_key(head_1MiB + scanned)` where the head is the first
`mcp.PREVIEW_SCAN_BYTES` (cheap; the file is already open) — or widen the backward overlap to the start of the file
for files ≤ 4 MiB. Apply the same to `_text_via_range_header`.

**R9-F3. The Recycle Bin move can still end in a permanent delete through a Windows prompt (AC-AC-5, SEC-7).**
`assistant/actions/shell.py:308-313` calls `SHFileOperation(FO_DELETE)` with `FOF_ALLOWUNDO | FOF_WANTNUKEWARNING |
FOF_SILENT | FOF_NOERRORUI` and no `FOF_NOCONFIRMATION` (correct so far — qa observed items landing in the Bin). When
the Bin cannot hold the item the shell does not fail: it shows "This file is too big to recycle. Do you want to
permanently delete it?" (owner window 0, so it can pop behind the Assistant) and deletes on Yes. Two triggers exist on
every Windows machine: the per-volume `MaxCapacity` and the `NukeOnDelete` policy. Read-only registry check on this
laptop: every `HKCU\…\Explorer\BitBucket\Volume\{guid}` has `MaxCapacity=26364` MB (≈26 GB, so a 30 GB disk image or
a large folder from the results list crosses it) and `NukeOnDelete=0`; a corporate policy can set `NukeOnDelete=1`,
after which every move becomes a permanent delete behind that prompt. The product's wording is "No menu, shortcut,
API or MCP tool anywhere in the product performs a permanent delete"; a path that ends in Windows asking "permanently
delete?" is still the product performing it. Not reproduced (that would delete something).
*Fix:* before calling, resolve the volume (`GetVolumeNameForVolumeMountPointW` → `\\?\Volume{guid}\`), read
`NukeOnDelete` and `MaxCapacity` for that guid (fall back to the `BitBucket` root values and `UseGlobalSettings`),
compute the item size (file: `st_size`; folder: a bounded walk, refuse when the walk hits the cap), and refuse with the
existing explanation style ("Not moved: it is larger than the Recycle Bin on this drive (26 GB) …" / "… this PC's
policy deletes immediately instead of recycling") when `NukeOnDelete` is set or the size exceeds the capacity.
Keep `FOF_WANTNUKEWARNING` as the second line. `--doctor` could print the two values.

**R9-F4. The executable-class list misses extensions that run code on double-click on this machine (SEC-6,
AC-AC-3).** `assistant/actions/shell.py:28-30` covers the PRD's list plus `.vbe .jse .wsf .msp .jar .cpl .pif`. Missing
and associated with a script host here (read-only `assoc`/`ftype`): `.py` → `Python.File` → `"C:\WINDOWS\py.exe" "%L"
%*` (runs the script; the development laptop and any Python-installed corporate laptop behave the same), `.pyw` →
`Python.NoConFile`, `.wsh` → `WSHFile`, `.settingcontent-ms` → `SettingContent` (the 2018 Office/Explorer abuse class),
`.msc` → `MSCFile`. Also worth adding regardless of local association: `.wsc .sct .vb .ws .psm1 .psd1 .ps1xml .cdxml
.inf .ins .isp .mst .shs .shb .application .appref-ms .appinstaller .diagcab .chm .library-ms .searchconnector-ms
.gadget .ahk .rb .pl .php .sh .command .desklink .mapimail`. Opening one of these from Assistant equals a double-click
in Explorer, so this is parity rather than a new capability, but AC-AC-3's purpose is to make the user confirm before
Assistant runs something — the confirmation list should at least cover what the machine will execute. *Fix:* extend
`EXECUTABLE_EXTS`, and consider a dynamic check (`AssocQueryStringW(ASSOCSTR_COMMAND)`; treat as executable when the
command's image is `wscript|cscript|powershell|pwsh|py|pyw|python|cmd|mshta|msiexec|rundll32|mmc`).

#### NOTE (hardening; none a merge gate)

**R9-N1. A `Range` header with more than 4300 digits is an unhandled 500.** `routes_files.py:61` `_RANGE_HEADER =
^bytes=(\d*)-(\d*)$` has no length bound; `int()` on a 5000-digit group raises `ValueError: Exceeds the limit (4300
digits)` out of `_parse_http_range` (observed for text, pdf and images); h11's default 16 KiB header limit admits it.
Fix: `\d{0,15}` like `_RANGE_PARAM`, or treat `ValueError` as "no range". Everything else in the Range matrix behaved:
`bytes=-1` → 206 of the last byte; `bytes=0-` → 206 of the whole 3.2 MB (under the 4 MiB cap); `bytes=5-3`,
`bytes=<size>-`, `bytes=-0` → 416 with `Content-Range: bytes */<size>`; multi-range, `abc`, `1-2-3` → ignored (200 JSON);
`bytes=-99999999999999999999` → whole file; `range=` param: `5-3`, `-5`, `abc`, 16 digits → 422; `99999999999999-` → 422.

**R9-N2. "Move to Recycle Bin" from the full page can never succeed (fail-safe functional bug).** `web/src/App.jsx:
301-315` shows its own confirmation modal and then posts `/v1/actions/recycle` with `{path}` only; the server answers
`{ok:false, needs_confirmation:true, message:"Move x to the Recycle Bin?"}` (observed), which the modal displays as an
error. The modal is the AC-AC-5 confirmation, so the re-POST should carry `confirm: true`. The popup side
(`search_ui.py:669-690` → `app.py:_action_done`) does it right. For qa/ui.

**R9-N3. `hydrate=1` is sent by the page and ignored by the server.** `web/src/preview/load.js:9` adds the parameter;
no server code reads it (grep); the pane then prints "Download was requested: …" although nothing was requested.
AC-PV-5 promises a download. Either implement (open the placeholder with `FILE_FLAG_OPEN_REPARSE_POINT` cleared is
exactly the hydration the rest of the pipeline avoids — decide deliberately) or change the text to "Assistant does not
download cloud files; open it once in Explorer and preview again". For product/qa.

**R9-N4. SVG is shown through a `blob:` URL in `<img>`; a blob URL has the page's origin and no CSP.** Scripts,
`onload`, external `<image>` and CSS `url()` inside an SVG are inert in `<img>` — observed: the SVG section of the
headless run produced zero beacon hits. If Edge's app-mode context menu offers "Open image in new tab" (not checked
here), the SVG would be opened as a document in the `127.0.0.1:<port>` origin and its script would run — without the
bearer (module variable in another document) or cookies (none exist), so it could reach only `/app/*` and the
exchange, which needs a nonce. Low. Hardening: pass SVG through DOMPurify (`USE_PROFILES: {svg: true, svgFilters:
true}`) into the same sandboxed `srcdoc` iframe the HTML preview uses, or at least `onContextMenu={e =>
e.preventDefault()}` on preview images. The `/v1/files/preview` SVG response itself is fine: `image/svg+xml`,
`nosniff`, `Content-Disposition: inline`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline';
sandbox` (observed) — and it cannot be navigated to because the bearer is a header.

**R9-N5. Nonce exposure paths, assessed.** `fullpage.py:46-47,122` passes `--app=http://127.0.0.1:<port>/app/?launch=
<nonce>&q=<query>`; `web/src/api.js:104-115` reads both and `history.replaceState`s them away before the first
request. Until the exchange (well under a second) the nonce is visible in the Edge process command line (readable by
any same-user process through `Win32_Process`), in the profile's session/history files, and in the window title
before the page sets its own. All three are same-user-only; a same-user process can read the token file directly, so
the nonce adds no privilege; single use + 30 s + 16 outstanding + `compare_digest` (observed: replay 403, expiry 403,
20 mints keep 16, the oldest evicted). No change required. Profile hygiene worth adding to the Popen list:
`--disable-sync --disable-extensions --disable-background-networking --no-service-autorun`. Policy-force-installed
extensions (`ExtensionInstallForcelist`) apply to every profile and cannot be prevented by a non-admin app — record
as a known limit on managed laptops rather than something the code can fix.

**R9-N6. The Edge profile folder is neither deny-listed nor excluded.** `%LOCALAPPDATA%\Assistant\edge-profile`
(`fullpage.py:41-43`) holds that profile's `Cookies`, `History`, `Login Data`, `Preferences`; `denylist.DIR_PATTERNS`
covers `appdata/local/microsoft/edge/user data` and `index/excludes.DEFAULT_EXCLUDES` covers `AppData/Local/Microsoft/
Edge/`, neither covers `AppData/Local/Assistant/`. With a root over the profile these files are indexed (most are
caught as binary at preview time, `History` has no extension so `_looks_binary` catches it). Same class as R7-F1. Fix:
add `appdata/local/assistant` to `DIR_PATTERNS` (one line, M3b-0's file).

**R9-N7. The Origin check is host-only.** `auth.py:26-31` accepts any port on `127.0.0.1`/`localhost`; observed: the
exchange answered 200 to `Origin: http://127.0.0.1:9999`. Consequence is nil today — no CORS headers are ever sent so
the response is opaque to another origin; the JSON POST preflight gets 401 (observed `OPTIONS` → 401); every `/v1`
route needs the bearer (observed 401 with other-port Origin plus a `Cookie`). Accepted as designed (R5-N10 class).
Optional: require the Origin port to equal the server port.

**R9-N8. Rename and Recycle act on the resolved target of a symlink or junction, not the link.** `shell.py:276,317`
use `_vet`'s resolved path; a junction inside a root pointing to another in-root folder gets its *target* renamed or
recycled. Not a boundary escape (`resolve_in_roots` requires the target in-root) and the Bin makes it reversible, but
it is not what the row showed. Consider operating on the given path when `os.lstat` says reparse point.

**R9-N9. `_find_window` adopts any new Edge window when the launched pid's window is not found.** `fullpage.py:82-84`.
With Edge's background mode on, `msedge.exe` hands the URL to the running process and exits, so the pid never
matches; if the user opens a normal Edge window in that 15 s, `close()` sends it `WM_CLOSE`. Functional; prefer
matching by window title (`Assistant - file search`) plus class, or the `--user-data-dir` process tree.

**R9-N10. npm audit: 4 low, all one katex advisory (prototype pollution can bypass trust restrictions) via mermaid
11.17.2 and markmap-lib 0.18.12.** Markmap is imported as `markmap-lib/no-plugins` so its katex plugin is not in the
bundle; Mermaid reaches katex only for `$$…$$` math in labels and the advisory needs a pre-existing prototype
pollution. No path found; accept, revisit when mermaid 12 passes the age rule. `web/package.json` pins exact versions.

**R9-N11. `folder_listing` lists children regardless of exclude rules and hidden/system flags** (`shell.py:350-377`;
names, sizes, dates only; deny-listed children hidden — observed `hidden_protected` count). Fine by design; recorded
because `GET /v1/search` would not show the same entries.

**R9-N12. lstat-then-open window.** `routes_files.py:221-244` decides placeholder/size on `os.lstat`, then opens;
`_handle_ok` re-vets the *final path* through the handle (roots, deny-list, own folder — R7-N2 closed) but does not
re-read the attributes through the handle, so a same-user swap of a plain file for a placeholder between the two calls
would hydrate it. Same-user only, sub-millisecond window. Hardening: `win32file.GetFileInformationByHandle(h)[0]`
attributes check after `_handle_ok`.

### Assessments asked for

- **`style-src 'unsafe-inline'` + the style guard as the combined defence.** `'unsafe-inline'` is unavoidable (Mermaid and
  Markmap emit `<style>`, React emits `style=`); with it, attacker CSS can reach the live page only through the sinks the
  three layers cover: Mermaid's config CSS (now locked by `secure`; observed: directive and front matter both ignored,
  diagram still drawn), Mermaid `style`/`classDef` values (grammar rejects `url(`; observed parse error), and SVG files (now
  in a sandboxed opaque-origin frame). What CSS can do without a network fetch is restyle inside `#pv-mermaid-N` or inside
  the frame — no exfiltration primitive. Every fetch a stylesheet can cause (`url()`, `@import`, `image-set()`, `src()`,
  `@font-face`) is governed by `img-src`/`font-src`/`style-src`, all `'self'` plus `blob:`/`data:`, so the worst case is a
  same-origin probe to `/v1/...` without the bearer (401) or to a public `/app/` file. The guard is a belt, and a bypassable
  one (R10-N1); the CSP header is the load-bearing control; the `secure` list removes the vector at its source. Keep all
  three; do not let the guard's existence justify loosening the header.
- **`'wasm-unsafe-eval'`.** Needed and sufficient: `pdf.worker.min-CjEcRF4W.mjs` calls `new WebAssembly.Module(...)`,
  `new WebAssembly.Instance(...)` and `WebAssembly.instantiate(...)` for the vendored `openjpeg.wasm`, `jbig2.wasm`,
  `qcms_bg.wasm`; the worker script is served with the same header (observed), so the directive has to be in the header, not
  only on the page. The main bundle has no `WebAssembly.*` call (the string occurs only in highlight.js keyword tables), no
  `eval`/`Function`, no inline scripts, no external hosts; the page booted, searched, rendered Mermaid and the SVG frame with
  no CSP report other than the hostile ones listed here. Nothing else is required (`'unsafe-eval'` must stay out).
- **srcdoc meta CSP vs page CSP.** Both enforced — see R9-N4 above (two reports per blocked URL, one per policy).

#### NOTE

**R10-N1. The style guard's regex is bypassed by CSS escapes; the CSP catches what it misses.** `styleGuard.js:3` tests the
literal `url(`; the CSS tokenizer decodes escapes before deciding a token is `url(`, so `\75rl(http://...)` passes the guard
and is a real `url()`. Observed in the page: `guardRegexMatches=false`, `getComputedStyle(...).backgroundImage ==
'url("http://<beacon>/css-escape-main")'`, then `Loading the image ... violates ... "img-src 'self' blob: data:"`, no beacon
hit; inside the SVG frame the same for `<style>circle{fill:\75rl(...)}</style>` and `style="fill:\75rl(...)"` (both kept by
the guard, both blocked by both policies). Belt only — the CSP is what stopped it. Hardening: decode CSS escapes
(`\\[0-9a-fA-F]{1,6}\s?` and `\\.`) before testing, or drop any `<style>`/`style=` containing a backslash; also match
`-webkit-image-set(`. `<feImage href>` to an external host also survives DOMPurify's svgFilters profile (observed) and is
CSP-blocked; consider adding `feImage` to the SVG `FORBID_TAGS`.

**R10-N2. The Recycle Bin pre-check does not read the group-policy value and skips the check when the per-volume key is
missing.** `shell.py:339-357` reads only `HKCU\...\BitBucket\Volume\{guid}`; the corporate mechanism for "delete immediately"
is `HKCU|HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\NoRecycleFiles=1` (not present on this laptop,
read-only check), and a volume that has never had its Bin properties opened has no `{guid}` key, in which case `_bin_settings`
returns `(None, None)` and `_bin_problem` returns `None` (observed with the monkeypatched reader). Fix: read `NoRecycleFiles`
(both hives) and refuse when set; when the volume key is missing fall back to the `BitBucket` root `MaxCapacity` if present,
otherwise skip only the size check (current behaviour) and say so in `--doctor`.

**R10-N3. R9-F2 residual for files larger than 1 MiB.** The head scan covers the first MiB; a key whose header sits beyond
that is caught only if the window reaches within 64 bytes of it. Observed, header at 2 097 156: `range=2097146-2097556` →
`protected`; `range=2097256-2097556` → `kind=text`, key body in the answer. Same trust class as before (bearer holder only;
the page's own walk from 0 stops at the refusing window). Fix: make the backward overlap 8 KiB (a PEM body is under 8 KiB up
to RSA-8192), which closes "window holds the body but not the header" for every file size at no measurable cost.

**R10-N4. `_runs_code` edge cases.** `shell.py:147-150`: an unquoted command with spaces (`C:\Program Files\X\python.exe "%1"`)
yields the stem `Program`; `python3`/`python3.13` stems are not in `SCRIPT_HOSTS`; a command longer than 2048 chars makes
`AssocQueryStringW` fail and the extension is treated as non-executable. On this laptop `.py` is associated with an editor, so
the fixed list is what protects it — keep both mechanisms. Add `python3*`, `java`, `javaw`, `node`, `ruby`, `perl`, `php`,
`bash`, `wsl`, `msiexec`, `mmc`, `hh` to `SCRIPT_HOSTS` and parse the image with `CommandLineToArgvW` or shlex-style quoting.
