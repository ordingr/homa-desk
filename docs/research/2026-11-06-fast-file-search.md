## 1. Question

Can Assistant ship an Everything-class (voidtools) instant file finder for one heavy developer on two Windows 11 laptops — a personal one with admin rights and a corporate-managed one almost certainly without — that stays private and light on CPU, and what should the PRD pin down for engine, query syntax, excludes, preview, actions, hotkey, "Ask Claude" and the MCP server?

Scope decisions relayed by the tech-lead from the user during this research (treated as constraints, not findings):

1. v1 matches file names and paths only; content search is a later, opt-in, per-folder feature.
2. Both laptops are targets; the engine must have a no-admin mode. MFT/USN is the fast path where admin exists.
3. UI is its own popup window opened by a global hotkey; the Assistant overlay's text box can also open it.
4. v1 also includes: filter chips (Docs/Sheets/PDF/Images/Code/Folders) plus a modified-date filter; saved searches; right-click actions (open with, rename, properties, move to Recycle Bin — never permanent delete); an "Ask Claude about this file" action.
5. A local MCP server is a v1 requirement so Claude Code, Claude Desktop and other MCP clients can search and fetch metadata/preview text.
6. Reference build exists (photos only, no code): a "fastsearch" web UI at `localhost:5180` showing "0.3M entries", "42.3 ms" query time, a "substring" match-mode badge, Name/Ext/Date sort, coloured extension tags, highlighted matches, path + date per row, a right-hand Markdown preview pane; gestures Click = preview, Dbl-click = open, Ctrl+dbl-click = open folder, Ctrl+click = multi-select, Ctrl+right-click = copy path; header Settings / About / theme / Filters. The Assistant overlay had a FILES mode (compact results, details line, Open = Enter, MD Vault = Ctrl+M, Explorer = Ctrl+Enter, Fastsearch folder = Ctrl+F, Full page = F11, Tab switches mode, "index from <date>").
7. (Added later, see section 10.) The shipped app must run as `.py` under an already-approved Python 3.10+ with pip-only dependencies and no compiled executable of our own, because the work laptop's AppLocker blocks unknown `.exe` files.

## 3. Findings

### Q1. How Everything gets its speed, and what a non-admin process can do

**How Everything works.** Initial index = direct read of the NTFS volume's file table via the USN enumeration FSCTL; live updates = the NTFS USN change journal, which the OS maintains even while Everything is closed. Names only (plus size/dates since 1.4). Sources: voidtools FAQ — "Everything will automatically keep your NTFS indexes up to date with the NTFS USN Journal", "Changes will not be missed when Everything is not running" (https://www.voidtools.com/faq/); developer post "NTFS has a master file table which will make initial index very fast ... Everything uses the USN Journal for both NTFS and ReFS volumes" (https://www.voidtools.com/forum/viewtopic.php?p=57345). Confidence: High.

**Published cost (voidtools FAQ, verbatim):** "A fresh install of Windows 11 (about 250,000 files) will take about 5 seconds to index" and "will use about 35 MB of ram and less than 14 MB of disk space"; "1,000,000 files will take about 1 minute" and "will use about 100 MB of ram and 45 MB of disk space" (https://www.voidtools.com/faq/). Confidence: High (vendor doc; the 1-minute figure includes service start-up and is for an SSD-class machine).

**Admin is required for MFT/USN — every source agrees.**
- voidtools FAQ: "NTFS indexing requires the Everything service or running 'Everything' as administrator" and Everything "requires administrative privileges for low level read access to NTFS volumes for NTFS indexing" (https://www.voidtools.com/faq/).
- Developer, 2026: "You'll need admin privileges to access the USN Journal on system volumes" and "MFT indexing cannot be used for system drives when running as a standard user" (https://voidtools.com/forum/viewtopic.php?p=49086).
- Microsoft, CreateFile "Physical Disks and Volumes": "Direct access to the disk or to a volume is restricted ... The caller must have administrative privileges" (https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea). FSCTL_ENUM_USN_DATA and FSCTL_READ_USN_JOURNAL need a `\\.\C:` volume handle and are not available over SMB (https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_enum_usn_data, https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_usn_journal). Microsoft names the Administrators group, not a single privilege (https://learn.microsoft.com/en-us/windows/win32/fileio/creating-modifying-and-deleting-a-change-journal).
- Library authors confirm: `ntfs-reader` — "Opening a raw volume needs an elevated (administrator) process"; `usn-journal-rs` — journal and MFT enumeration "require Windows and an Administrator process" (https://github.com/kikijiki/ntfs-reader, https://github.com/wangfu91/usn-journal-rs).
Confidence: High. No source claims a non-admin process can read the MFT or journal; UltraSearch, WizFile, WizTree, Listary, SwiftSearch all elevate for it (https://knowledgebase.jam-software.com/7580, https://discussion.listary.com/t/running-listary-on-office-pc-no-admin-rights/3923).

**How Everything "works without admin".** The "Everything Service" is the elevation split: a ~1 MB service runs privileged, reads volumes, and hands file names to the standard-user GUI over a named pipe; without it Everything falls back to "folder indexing", which the developer confirms is literally `FindFirstFile` for the scan and `ReadDirectoryChanges` for monitoring (https://www.voidtools.com/support/everything/everything_service/, https://voidtools.com/forum/viewtopic.php?p=54633). Installing the service needs admin ("Everything installation requires administrative privileges", https://www.voidtools.com/support/everything/installing_everything/). Folder indexing "does not require administrative privileges or the Everything service", the initial scan "can take a few minutes", and "Fast rescan only works on NTFS" (https://www.voidtools.com/support/everything/folder_indexing/). Confidence: High.

**The no-admin path in depth (what the corporate laptop will run).**

| Aspect | Evidence | Expected for 1–2 M files | Confidence |
|---|---|---|---|

Important nuance from the reference build: it reported "0.3M entries", which suggests the prior crawl-based build with excludes applied covered ~300 k entries on the work laptop — well inside the warm/cold budgets above. Confidence: Medium (user photo).

**Where the crawl path is actually better even with admin:** Dev Drive (ReFS) buffers the USN journal and flushes it "every 30 seconds or so", so the developer advises "folder indexing instead" for immediate updates, and a 2026 ReFS driver change broke overlapped `FSCTL_READ_USN_JOURNAL` (https://www.voidtools.com/forum/viewtopic.php?p=77974). Also, an elevated process cannot see the user's mapped network drives ("Mapped network drives are not available when Everything runs as administrator", https://www.voidtools.com/support/everything/folder_indexing/). Confidence: Medium–High.

### Q3. Using Everything itself as the engine

- **Mechanism.** The SDK is "a DLL and Lib interface to Everything over IPC" using `WM_COPYDATA`; "Everything is required to run in the background" (https://www.voidtools.com/support/everything/sdk/). Alternatives: `es.exe` (needs Everything "installed and running"; `-json`/`-csv` export, `-sort`, `-count`, `-offset`, `-instance`, exit code 8 = IPC window not found) (https://www.voidtools.com/support/everything/command_line_interface/); HTTP server with `json=1`, HTTP Basic auth in plaintext, and it "binds to all available network interfaces" unless you set `127.0.0.1` (https://www.voidtools.com/support/everything/http/). Confidence: High.
- **Licence.** Everything is MIT plus the PCRE licence (https://www.voidtools.com/License.txt; developer: "Yes, Everything uses the MIT license", https://www.voidtools.com/forum/viewtopic.php?p=21270; commercial use OK, https://www.voidtools.com/forum/viewtopic.php?p=25104). The SDK page itself states **no licence**; whether `Everything64.dll` is covered by the same MIT grant is not published anywhere fetched. The Rust wrapper `everything-sdk` is **GPLv3** (https://docs.rs/crate/everything-sdk/latest). A dependency-free route exists: speak `WM_COPYDATA` yourself, as the MIT Python package `everyfile` does (https://pypi.org/project/everyfile/). Confidence: High on Everything's licence; Medium (adversarial gap) on the SDK DLL.
- **Session and admin constraints.** IPC is same-session only ("Session 1 cannot communicate with session 0 due to session isolation", https://voidtools.com/forum/viewtopic.php?p=57705; 1.5 beta: "only accepts IPC connections from clients in the same session"). Everything 1.4 Lite has no IPC. The 1.5 alpha runs as instance "1.5a" so the 1.4 SDK needs `-instance` or `alpha_instance=0` (https://www.voidtools.com/support/everything/multiple_instances/, https://www.voidtools.com/forum/viewtopic.php?p=36428). Confidence: High.
- **Is it realistic on the corporate machine?** Only if IT already deploys Everything with its service. The portable zip runs without admin ("No changes are made to the system") but then NTFS indexing is unavailable and it does the same `FindFirstFile` folder indexing we would do ourselves, while adding a second tray process, a UAC nag for the service, and an unsigned-for-us dependency that AppLocker/WDAC may block (https://www.voidtools.com/support/everything/installing_everything/, https://www.voidtools.com/forum/viewtopic.php?p=74285). Verdict: not a v1 dependency; at most an optional "use Everything if present" accelerator on the personal laptop. Confidence: Medium.
- **Pros/cons vs our own index.** Pros: zero indexing code, proven 1 M-file/minute performance, journal-backed deltas. Cons: external process must be running in the same session; no relevance ranking (see Q5); licence gap on the DLL; no path to MCP/preview without our own daemon anyway; useless on the no-admin machine.

### Q4. Non-NTFS sources: what breaks

- **SMB/NAS.** USN FSCTLs are "Server Message Block (SMB) 3.0 protocol: No" (Microsoft, Q1 links). Everything folder-indexes shares; change buffers are "limited to 64 KB"; offline shares make lookups "take several seconds to time out" (https://www.voidtools.com/support/everything/folder_indexing/). Non-Windows SMB servers (a QNAP NAS included) "may not properly support ReadDirectoryChangesW", and a dead server leaves the watcher silently hung with "no built-in timeout mechanism" (https://learn.microsoft.com/en-us/archive/blogs/winsdk/filesystemwatcher-follies). Implication: index shares on a schedule, with a per-share timeout, and never block the UI on them. Confidence: High.
- **OneDrive Files On-Demand.** Placeholders are real NTFS entries (1 KB) carrying `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` (0x00400000) / `FILE_ATTRIBUTE_RECALL_ON_OPEN`; reading content "will cause at least some of the file/directory content to be fetched from a remote store" (https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants, https://learn.microsoft.com/en-us/windows/win32/cfapi/build-a-cloud-file-sync-engine). Rule: enumerate names/attributes only; never open placeholders during indexing or preview without a "this will download" step; `FIND_FIRST_EX_ON_DISK_ENTRIES_ONLY` skips virtual entries (https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstfileexa). Everything had at least one unresolved report of On-Demand folders missing from a folder index (https://www.voidtools.com/forum/viewtopic.php?p=67483). Confidence: High (Microsoft) / Medium (Everything report).
- **exFAT/FAT32 USB.** No MFT, no journal; crawl + ReadDirectoryChangesW only; "exFAT volumes do not support fast rescanning" and Everything 1.4 cannot auto-index them (https://www.voidtools.com/faq/, https://www.voidtools.com/forum/viewtopic.php?p=79118). Treat removable drives as opt-in roots with a rescan on insert. Confidence: High.
- **ReFS / Dev Drive.** Journal yes, MFT no; initial index "several minutes" via journal; 30 s change lag on Dev Drive (Q1). Confidence: Medium–High.

### Q5. Query design across Everything, Google, fzf, ripgrep and launchers

- **Everything** (https://www.voidtools.com/support/everything/searching/ and `/search_syntax/`, `/search_modifiers/`, `/search_functions/`): space = AND, `|` = OR (OR binds tighter than AND by default), `!` = NOT, `"..."` literal, `*`/`?` wildcards (`**` crosses `\`), implicit substring match, modifiers `case:`, `ww:`, `path:`, `regex:`, `file:`, `folder:`; functions `ext:mp3;flac`, `size:>1gb`, `dm:today` / `dm:7days` / `dm:2025-07-01..2026-06-30`, `parent:`, `attrib:`, drive filters `c:`. **No relevance ranking**: "By default the results are sorted by Name, then Path" and sort columns are the only ordering (Run Count, Date Run, Date Recently Changed exist as columns, not as a blended score) (https://www.voidtools.com/support/everything/results/). Confidence: High.
- **Google** (https://support.google.com/websearch/answer/2466433): `"phrase"`, `-exclude`, `site:`, `filetype:`, `before:`/`after:`; "Do not put spaces between the operator and your search term." `OR` and `*` are no longer on the official page. Confidence: High.
- **fzf** (https://github.com/junegunn/fzf, `src/algo/algo.go`): space = AND, `'exact`, `^prefix`, `suffix$`, `!negate`, `|` OR; scoring gives +8 for word/path boundary, +7 camelCase, +4 consecutive, first-char bonus x2; `--scheme path` bonuses characters after `/`; tiebreak = shorter length. Confidence: High (source read).
- **VS Code Quick Open** (`src/vs/base/common/fuzzyScorer.ts`): start-of-string +8, after path separator +5, after `_ - . space` +4, camelCase +2, consecutive runs weighted; label (file name) matches rank above path matches unless the query contains a separator; recently opened editors are shown first; `"quoted"` forces contiguous match (fetched raw source via GitHub). Confidence: High.
- **Frecency.** Raycast ranks exact alias > title fuzzy score > "Frecency (a blend of frequency and recency)" (https://manual.raycast.com/search-bar.md). Mozilla's new-frecency trick: each visit contributes `points × e^(−λ·age)` with half-life 30 days, stored as a single date so sorting needs no recomputation (https://wiki.mozilla.org/User:Jesse/NewFrecency). Flow Launcher adds `selected_with_this_query × 5 + selected_any × 1` to the score with no decay (`Flow.Launcher/Storage/UserSelectedRecord.cs`). Confidence: High.
- **ripgrep** is a content tool; its `rg --files` + `.gitignore`-aware walker (`ignore` crate) is relevant to Q6/Q7, not to query syntax (https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md).

**Recommended minimal v1 syntax (my synthesis, grounded above; see section 12 for the conflict with the reference build's flags):** terms separated by spaces are ANDed substring matches against the file name (Everything/fzf/VS Code all do this); `"quoted phrase"` = contiguous match including spaces; leading `-term` = NOT (Google's form, familiar to the user; Everything's `!` can be an accepted alias); `ext:md,pdf` (comma or `;` list, whole-extension match); `path:term` or any term containing `\` or `/` matches against the full path (VS Code's rule); `*`/`?` wildcards. Defer `|` OR, regex, size and date functions to the chips/filters rather than syntax (the user asked for a date filter as a control). Ranking: exact name match > name starts with query > word-boundary match in name > match in path, tiebreak by shorter name then recency; blend in a frecency bonus for files the user has opened from the app (exponential decay, half-life 30 days). "Match mode: substring" badge as in the reference build makes the behaviour legible.

### Q6. Exclude/include design and a default list

- Everything's exclude model: index-level "Exclude folders" list, "Exclude files" wildcard list (`*.db`), "Include only files", and attribute toggles for hidden/system; filters accept wildcards or `regex:`. **It ships no default excludes**; users add `$RECYCLE.BIN` and `System Volume Information` by hand (https://www.voidtools.com/support/everything/options/, https://www.voidtools.com/support/everything/ini/). Confidence: High.
- gitignore semantics worth borrowing: `**/` any depth, trailing `/` = directories only, `!` re-include, last match wins, "It is not possible to re-include a file if a parent directory of that file is excluded" (https://git-scm.com/docs/gitignore). Confidence: High.
- Windows Search default exclusions include `\Windows\`, `\ProgramData\`, `\Users\*\AppData\`, `\Users\*\AppData\Local\Temp\`, `\$Recycle Bin\`, `\Windows\CSC\` (https://learn.microsoft.com/en-us/windows/win32/search/-search-3x-wds-included-in-index; page dated 2018). Confidence: High (official, dated).
- Volume of noise: WinSxS is tens of thousands of hard-linked entries (Microsoft: Explorer overstates it because of hard links, https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/manage-the-component-store); a single Angular `node_modules` ≈ 55 k files (my arithmetic from https://huggingface.co/datasets/dimhold/install-graph: 7,904 duplicated files = 14.4%); a microservice `node_modules` ≈ 19 k files, a Python venv ≈ 10 k `[search-only]`. Confidence: Low–Medium on counts; High that they dominate a developer's file count.

**Recommended default excludes (gitignore-style, directory patterns unless noted):**
- System: `C:\Windows\` (covers WinSxS, Installer, Temp), `$RECYCLE.BIN/`, `System Volume Information/`, `C:\ProgramData\Microsoft\Search\`, `pagefile.sys`, `hiberfil.sys`, `swapfile.sys`, `*.vhdx` (Docker/WSL disks).
- Per-user: `AppData/Local/Temp/`, `AppData/Local/Microsoft/WindowsApps/`, `AppData/Local/Packages/`, `AppData/Local/Microsoft/Edge/`, `AppData/Local/Google/Chrome/` (browser caches; make this one easy to toggle), `AppData/Local/Docker/`.
- Developer: `**/node_modules/`, `**/.git/` (keep the repo, drop the object store — ripgrep's default behaviour), `**/.venv/`, `**/venv/`, `**/__pycache__/`, `**/target/`, `**/bin/`, `**/obj/`, `**/.gradle/`, `**/.m2/`, `**/.nuget/packages/`, `**/.cache/`, `**/.vs/`, `**/dist/`, `**/build/`, `**/.next/`, `**/.turbo/`.
- Attribute toggles: hidden and system files excluded by default except an allow-list for dotfiles the user cares about (`.env` is also a secrets concern — see MCP safety).
- Include rules: explicit root list per machine (e.g. `C:\Users\<user>\`, `C:\AI Projects\`, `D:\`), network shares as scheduled roots, removable drives opt-in. Include rules override excludes only when more specific (gitignore's "last match wins" within a file, but a parent-excluded folder cannot be re-included — surface that in the settings UI).

### Q7. Optional file-content search (kept short per scope)

Evidence that it is expensive: Everything 1.5's own content indexing keeps "content in memory", defaults to only `*.doc;*.docx;*.pdf;*.txt;*.xls;*.xlsx`, and "Indexing over 1GB of text is not recommended"; a user who enabled it broadly saw RAM "shoot up to 26 GB" (https://voidtools.com/forum/viewtopic.php?p=35395, https://www.voidtools.com/forum/viewtopic.php?p=68457). Windows Search itself says "If the Indexer indexes more than 400,000 items, you may begin to see performance issues" and caps at 1 M (https://learn.microsoft.com/en-us/troubleshoot/windows-client/shell-experience/windows-search-performance-issues). Index-size reference points: SQLite FTS5 is 45% of corpus at `detail=full`, 8% at `detail=none` (https://www.sqlite.org/fts5.html); Zoekt's positional trigram index is "about 3x the corpus size" (https://github.com/sourcegraph/zoekt/blob/main/doc/design.md); Quickwit/Tantivy indexes at roughly 20–50 MB/s on 4 cores, i.e. minutes of full-fan CPU per few GB (https://quickwit.io/blog/benchmarking-quickwit-engine-on-an-adversarial-dataset). ripgrep searches a warm Linux kernel tree in 0.08 s but every published number is warm-cache (https://github.com/BurntSushi/ripgrep, https://burntsushi.net/ripgrep/). Confidence: High.

Recommendation for later: v2 opt-in, per-folder, two tiers — (a) on-demand grep over the current result set using the `grep-searcher`/`ignore` crates in-process (zero idle cost, MIT/Unlicense), and (b) if the user wants persistent content search for a few folders, SQLite FTS5 with `detail=none` and contentless tables (≈8% of text, no copy of the text) restricted to text/code extensions with a hard per-file size cap and binary sniffing. PDF/Office extraction is the real CPU cost (≈0.1–0.3 s per PDF, https://github.com/py-pdf/benchmarks); keep it out until asked. (Under the Python constraint of section 10, tier (a) becomes Python `re` over files or a scoped on-demand scan, and tier (b) is the stdlib `sqlite3` module's FTS5, which is compiled into CPython's bundled SQLite on Windows.)

### Q9. Open file, open containing folder with selection, copy path

- **Reveal in folder.** Do not spawn `explorer.exe /select,...`: quoting rules break with commas/spaces when the host API quotes the argument, the exit code is meaningless, and a new window opens every time (community reports, https://forum.photostructure.com/t/open-file-in-folder-does-not-always-work-on-windows/448). The proper API is `SHOpenFolderAndSelectItems` after `CoInitialize` (https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems) with PIDLs from `ILCreateFromPathW` (MAX_PATH-limited, https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-ilcreatefrompathw). Electron `shell.showItemInFolder` and Tauri `revealItemInDir` both already call it (https://github.com/electron/electron/blob/main/shell/common/platform_util_win.cc, https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/opener/src/reveal_item_in_dir.rs). Confidence: High.
- **Long paths and Unicode.** Explorer does not honour `LongPathsEnabled` ("It is possible to create a path with the Windows API that the shell user interface is not able to interpret properly", https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation). Strip `\\?\` (and rewrite `\\?\UNC\` to `\\`) before any shell call or clipboard copy; expect reveal to fail past ~260 characters and fall back to opening the parent folder. Unicode is fine through the W APIs; percent-encoded URLs are not decoded by Explorer. Do not Unicode-normalise paths. Confidence: High.
- **Open with default app.** `ShellExecuteExW` with `SEE_MASK_NOASYNC | SEE_MASK_FLAG_LOG_USAGE`; `SE_ERR_NOASSOC` → `openas` verb or `SHOpenWithDialog` with `OAIF_EXEC` (Windows 10+ ignores the registration flags) (https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow, https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenwithdialog). Treat `.lnk .url .exe .com .scr .bat .cmd .ps1 .vbs .js .hta .msi .reg` as executable classes requiring confirmation — `ShellExecute` on a `.lnk` runs its target. Tauri's opener plugin shells through PowerShell by default unless the `shellexecute-on-windows` feature is on (https://github.com/Byron/open-rs/blob/main/src/windows.rs); Electron `shell.openPath` has no executable guard. Confidence: High.
- **Copy path.** Explorer's "Copy as path" wraps in quotes (community); offer quoted and unquoted. Electron ≥40 deprecates renderer clipboard use; Tauri needs `clipboard-manager:allow-write-text` (https://www.electronjs.org/docs/latest/api/clipboard, https://v2.tauri.app/plugin/clipboard/). Confidence: High.

### Q10 (added scope). Global hotkey

- All three candidate stacks bottom out in Win32 `RegisterHotKey`: Tauri's `global-hotkey` crate (adds `MOD_NOREPEAT`, hidden message window; https://github.com/tauri-apps/global-hotkey), Electron via Chromium `SingletonHwndHotKeyObserver` (no `MOD_NOREPEAT` — debounce) (https://raw.githubusercontent.com/chromium/chromium/main/ui/gfx/win/singleton_hwnd_hot_key_observer.cc), .NET via P/Invoke or `NHotkey` (Apache-2.0, https://github.com/thomaslevesque/NHotkey). Confidence: High.
- Rules (https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey): system-wide unique, fails with `ERROR_HOTKEY_ALREADY_REGISTERED` (1409) — Electron "fails silently" (https://www.electronjs.org/docs/latest/api/global-shortcut), Tauri surfaces "Hotkey already registered" (https://github.com/tauri-apps/tauri/issues/9806); "Keyboard shortcuts that involve the WINDOWS key are reserved for use by the operating system"; F12 reserved for the debugger; registering thread needs a message loop. Confidence: High.
- Elevated windows: `RegisterHotKey` keeps firing when an admin window has focus (it is a system match, not a hook), but *activating* your popup over a high-integrity window can fail; PowerToys Run switched to RegisterHotKey for this reason and offers a "centralized keyboard hook" fallback (https://github.com/microsoft/PowerToys/issues/13517, https://learn.microsoft.com/en-us/windows/powertoys/run). Low-level keyboard hooks are blocked by UIPI unless the app has `uiAccess` (signed, installed under Program Files — impossible without admin) (https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview). Confidence: High.
- Defaults and conflicts: PowerToys Run uses Alt+Space, which is the window system menu since Windows 3 and a documented complaint (https://github.com/microsoft/PowerToys/issues/7350); Command Palette uses Win+Alt+Space; Everything ships no factory hotkey and its developer recommends Ctrl+Space `[forum]` (https://www.voidtools.com/forum/viewtopic.php?p=67045) — but Ctrl+Space toggles CJK IMEs. Full-screen RDP (default "Only when using the full screen") and Citrix Workspace forward keys to the remote session, so expect the hotkey to be swallowed there; PowerToys ships an "Ignore shortcuts in full-screen mode" option as the pattern to copy (https://learn.microsoft.com/en-us/windows/win32/termserv/terminal-services-shortcut-keys, https://support.citrix.com/external/article/CTX583924/citrix-workspace-app-for-windows-shortc.html). Confidence: Medium–High.
- Corporate machines: no Group Policy blocks `RegisterHotKey`; the real blocker is AppLocker/WDAC refusing an unsigned per-user executable under `%LOCALAPPDATA%` (Microsoft warns against path rules for "standard user writable locations") (https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/working-with-applocker-rules). Code-sign the binary. Confidence: High. (Superseded in part by section 10: the user's README confirms AppLocker blocks unknown executables on the work laptop, which is why the reference build is pure Python.)

### Q11 (added scope). Right-click actions

- **Recycle Bin, never permanent.** `IFileOperation` (STA thread only — "For MTA, you still must use SHFileOperation") with `FOF_ALLOWUNDO | FOFX_RECYCLEONDELETE | FOF_WANTNUKEWARNING`, then check `GetAnyOperationsAborted` (https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifileoperation, https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags). `FOF_WANTNUKEWARNING` = "Send a warning if a file or folder is being destroyed during a delete operation rather than recycled" — that is the hook that prevents silent permanent deletion on network shares and exFAT/USB, which have no bin (community-confirmed, no primary Microsoft page). Pre-check `GetDriveTypeW` and refuse remote/removable deletes in v1 to honour "never permanent". Framework wrappers: Electron `shell.trashItem` (no flag control); Rust `trash` crate (MIT, uses `IFileOperation` with `FOF_NO_UI | FOF_ALLOWUNDO | FOF_WANTNUKEWARNING`, https://github.com/Byron/trash-rs); .NET `FileSystem.DeleteFile(path, UIOption.OnlyErrorDialogs, RecycleOption.SendToRecycleBin)` (default is permanent — always pass the option) (https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.fileio.filesystem.deletefile). Confidence: High.
- **Rename.** `IFileOperation::RenameItem` keeps undo and shell notifications (https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-renameitem); `MoveFileExW` does not notify Explorer `[inference]`. Validate names: forbidden `< > : " / \ | ? *`, reserved `CON PRN AUX NUL COM1–9 LPT1–9` including with extensions ("NUL.txt ... equivalent to NUL"), no trailing space or period (https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file). Confidence: High.
- **Properties.** `ShellExecuteExW` verb `properties` with `SEE_MASK_INVOKEIDLIST` on a pumping STA thread; the sheet is modeless in your process, so the thread must stay alive (https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow). `SHObjectProperties` is the simpler but "may be altered or unavailable" alternative. Confidence: High.
- **Open with.** See Q9. **Full Explorer context menu** (`IContextMenu`) is feasible only with a native HWND and loads third-party shell extensions into the host; the Files app isolates it in a separate server process (https://raw.githubusercontent.com/files-community/Files/main/src/Files.App/Utils/Shell/ContextMenu.cs). Ship the five explicit verbs first. Confidence: High.
- Reference-build gesture set (click = preview, double-click = open, Ctrl+double-click = open folder, Ctrl+click = multi-select, Ctrl+right-click = copy path) is compatible with all of the above; the plain right-click becomes the verb menu.

### Q13 (added scope). Local MCP server

- **Transport.** The spec is now at revision 2026-07-28 and is "a stateless protocol" with no `initialize`/session IDs; stdio is "client-launched subprocess", Streamable HTTP is "an independent process that can handle multiple client connections" (https://modelcontextprotocol.io/specification/latest/basic/transports, https://modelcontextprotocol.io/specification/2026-07-28/changelog). HTTP+SSE is deprecated ("New implementations SHOULD NOT adopt it"). For a singleton indexer that already serves a web UI, Streamable HTTP on the same port is the fit; stdio would spawn one indexer per client. Spec security text for local HTTP: servers "MUST validate the Origin header ... respond with HTTP 403", "SHOULD bind only to localhost (127.0.0.1)", "SHOULD implement proper authentication" (https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http); the best-practices page says local servers should "Use the stdio transport" or "Require an authorization token" (https://modelcontextprotocol.io/specification/latest/basic/security_best_practices). A locally minted bearer token is spec-sanctioned; OAuth is not required. Confidence: High.
- **Client support.** Claude Code: `claude mcp add --transport http <name> <url> --header "Authorization: Bearer ..."` (https://code.claude.com/docs/en/mcp). Claude Desktop: local servers are stdio via `claude_desktop_config.json`; "custom connectors" require an HTTPS URL reached from Anthropic's cloud, so localhost HTTP is not reachable that way; the sanctioned local packaging is a `.mcpb` Desktop Extension wrapping a stdio server (https://modelcontextprotocol.io/quickstart/user, https://claude.com/docs/connectors/custom, https://www.anthropic.com/engineering/desktop-extensions). Hence: native Streamable HTTP for Claude Code and others, plus a ~50-line stdio shim forwarding to it for Claude Desktop (prior art: `mcp-remote` MIT, `mcp-proxy` MIT, https://github.com/geelen/mcp-remote, https://github.com/sparfenyuk/mcp-proxy). Confidence: High.
- **SDKs (GitHub/registry data fetched 2026-11-06).** C# `ModelContextProtocol` 2.3.1 (2026-11-03), 4.6 k stars, Apache-2.0, maintained with Microsoft, stdio + Streamable HTTP via ASP.NET Core `MapMcp` (https://github.com/modelcontextprotocol/csharp-sdk). Rust `rmcp` 3.9.0 (2026-11-05), 4.1 k stars, Apache-2.0, Streamable HTTP server mounts on axum, stateless by default for 2026-07-28 clients (https://github.com/modelcontextprotocol/rust-sdk). TypeScript v2.4.0 (2026-10-23), 13.7 k stars, reference implementation, Express/Fastify/Hono helpers with Host validation (https://github.com/modelcontextprotocol/typescript-sdk). Python `mcp` 2.3.0 (2026-10-02), 24.8 k stars, MIT, DNS-rebinding protection on by default (only `127.0.0.1`/`localhost`/`[::1]` Hosts accepted) (https://github.com/modelcontextprotocol/python-sdk). All four are mature enough; C# and Rust let `/mcp` sit beside the web UI in one process and port. Confidence: High.
- **Prior art for Everything.** `mamertofabian/mcp-everything-search` (Python, 367 stars, MIT) wraps the SDK DLL, one `search` tool with `max_results` default 100, max 1000 (https://github.com/mamertofabian/mcp-everything-search); `elis132/everything-mcp` (31 stars, MIT) shells out to `es.exe`, five tools, default 50 results, hard cap 1000, explicitly avoids Everything's unauthenticated HTTP server (https://github.com/elis132/everything-mcp); `essovius/mcp-everything-search` has 16 tools including a side-effecting `open_file_location` — a counter-example. The official filesystem server has `search_files` (names only), `get_file_info`, `list_allowed_directories`, a `--read-only` flag, and refuses symlinks escaping the allow-list (https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem). Confidence: High.
- **Tool surface guidance.** Annotations are hints ("Clients should never make tool use decisions based on ToolAnnotations received from untrusted servers"); `readOnlyHint: true, openWorldHint: false` fits search/metadata/preview (schema https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2026-07-28/schema.ts). Protocol pagination covers only list endpoints, so search paging is your own `offset`/`limit` arguments. Anthropic: "More tools don't always lead to better outcomes"; return token-efficient results with pagination/truncation defaults (https://www.anthropic.com/engineering/writing-tools-for-agents). Claude Code warns at 10,000 output tokens and caps at 25,000; a tool can declare `_meta["anthropic/requiresUserInteraction"]: true` to force a prompt on every call (https://code.claude.com/docs/en/mcp). - **Safety.** Allow-list = the index's include/exclude rules, re-checked after resolving symlinks/junctions (Claude Code's own deny rules "apply when either the requested path or the file it resolves to matches", https://code.claude.com/docs/en/permissions). PRIVATE KEY-----` on preview text. Previews: byte and line caps, binary sniff, clearly delimited and labelled untrusted (prompt-injection). Confidence: High on spec/doc quotes; the deny list itself is my synthesis.

### Q14 (added scope). What the reference build implies for the architecture

The photos describe a background indexer with a local HTTP API, a browser web UI (`localhost:5180`), and the Assistant overlay as a second, thin client with its own FILES mode. MCP becomes a third client of the same API. This favours a **web-technology UI** (the MD-Vault React components for Markdown/Mermaid/Markmap drop in unchanged; pdf.js, docx-preview, SheetJS are all browser libraries) over WPF/WinUI, where each preview type would need a separate native control or a hosted WebView2 anyway. The one thing a browser tab cannot do is own a global hotkey or a native popup — so the hotkey/popup needs a native host (Tauri window, Electron window, or a small .NET tray process hosting WebView2) that loads the same web UI. The "42.3 ms" query time over 0.3 M entries is consistent with an in-memory substring scan `[inference]`; a full-text-indexed name search should be well under that. Confidence: Medium (interpretation of photos). (Section 10 revises the "native host" sentence: under the Python constraint the host is a Python/tkinter or Edge `--app` window.)

## 5. Risks and unknowns

1. **Cold first-index time on the corporate laptop is unmeasured.** Only one anecdote (~30 s for 500 k entries) and voidtools' "a few minutes" exist. Cheapest experiment: a 50-line `FindFirstFileEx` walk timed on both laptops before the PRD fixes any number. (Python numbers: section 10.2.)
2. **Lossy change notifications.** `ReadDirectoryChangesW` will drop events during bulk operations (npm install, git checkout). Mitigation is designed (re-walk on overflow + scheduled rescan) but the user may see stale results for seconds to minutes after large changes; the "index from <date>" indicator must stay.
3. **AppLocker/WDAC on the work laptop** may block any unsigned per-user executable, regardless of stack. Needs an early check of what the machine allows (e.g. does Everything's portable zip run?) and probably code signing. (Confirmed by the user's README — section 10.1 — hence the pure-Python constraint.)
4. **Everything SDK DLL licence is unpublished.** If Everything is used as an optional accelerator, speak WM_COPYDATA directly or use es.exe rather than redistributing the DLL.
5. **Preview security.** MD-Vault runs mermaid with `securityLevel: 'loose'` and renders arbitrary HTML from Markdown; for files the user did not author, the previewer must use `'strict'`, DOMPurify on every HTML path, SVG via `<img>`, and a CSP with no inline scripts. Office/PDF renderers parse untrusted binaries in the webview — keep them in a sandboxed iframe or worker.
6. **OneDrive hydration.** A naive preview or hash step will download placeholder files; the indexer and previewer must check `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` first.
7. **NAS watchers.** QNAP SMB may not support `ReadDirectoryChangesW`, and a sleeping NAS leaves a hung watcher; shares need scheduled rescans and timeouts.
8. **Hotkey collisions** with PowerToys (Alt+Space), IMEs (Ctrl+Space), Citrix/RDP full-screen capture. Default must be remappable with a clear "already taken" message and a tray fallback.
9. **"Ask Claude" sends file content off-machine** — a direct tension with the user's privacy preference. The PRD must make what-is-sent visible and default to the least data (preview text, not whole file), and must not wire this to the MCP server's secrets deny-list bypass.
10. **MCP spec churn.** Revision 2026-07-28 removed sessions and deprecated Roots; SDKs handle legacy clients, but the tool surface should not depend on roots or sampling.
11. **Recycle Bin on non-local volumes** is not possible; "never permanent delete" requires refusing deletes on remote/removable paths or a very explicit warning.
12. **PPTX preview has no good client-side renderer**; expect text+images only or the Office preview handler (needs Office + native HWND).
13. **Reference build details are from photos and a README**; its index format, exclude rules and the "substring" match mode are not recoverable, so the PRD should treat it as UX inspiration, not a spec.

## 6. Recommendation

Build it: the user's two-machine constraint rules out Everything and every MFT-based commercial tool as the primary engine, and nothing surveyed offers ranking, preview, hotkey popup and MCP together. Design the engine around one "source" abstraction with two implementations — crawl + `ReadDirectoryChangesW` + persisted index everywhere (this is the v1 critical path and must be measured on the corporate laptop first), and an optional elevated MFT/USN helper or Everything-IPC accelerator where admin exists. Keep v1 to names and paths, ship a web UI served by a local daemon with the MD-Vault preview components, and treat content search, IPreviewHandler hosting and the full Explorer context menu as later tiers.

## 7. Recommendations for PRD (original, 2026-11-06 — superseded by sections 11 and 12 where they conflict)

**Engine**
- One daemon per machine (tray/background process, auto-start at login), owning the index, a local HTTP API on `127.0.0.1` (random or configured port, bearer token), the web UI, and the MCP endpoint. Clients: popup window (hotkey), browser full page (F11), Assistant overlay FILES mode, MCP.
- Source abstraction with two implementations: (a) **Crawl source** — `FindFirstFileEx(FindExInfoBasic | FIND_FIRST_EX_LARGE_FETCH)` per root, attributes from the enumeration record only, persisted index with "index from <timestamp>", `ReadDirectoryChangesW` per volume root with 64 KB buffer treated as hints, subtree re-walk on `ERROR_NOTIFY_ENUM_DIR`, scheduled full rescan (default daily, plus on start if last rescan > N hours), background CPU priority, pause on battery. Required on both machines; the only mode on the corporate laptop. (b) **Journal source** — elevated helper (scheduled task with highest privileges or a service) doing `FSCTL_ENUM_USN_DATA` + `FSCTL_READ_USN_JOURNAL`, feeding names to the daemon over a local pipe; optional, personal laptop only; `usn-journal-rs`/`ntfs-reader` (Rust) or P/Invoke (C#). Optional (c) **Everything accelerator** via WM_COPYDATA/es.exe if Everything is detected running — do not redistribute the SDK DLL.
- Acceptance numbers to validate, not assume: 300 k–2 M entries; first cold crawl ≤ 3 min on NVMe; warm rescan ≤ 10 s; query ≤ 50 ms for substring over 2 M names; idle RAM ≤ 300 MB; idle CPU ≈ 0. Record the actual measurements from both laptops in the PRD appendix.
- Non-NTFS: network shares as scheduled roots with per-share timeout and no live watcher by default; removable drives opt-in; OneDrive placeholders indexed by name but flagged, never hydrated by indexer or previewer without a click.

**Stack**
- Web UI (React; reuse MD-Vault's `MarkdownViewer`, `MermaidDiagram`, `MarkmapDiagram` with mermaid `securityLevel: 'strict'`) served by the daemon. Native host for hotkey + popup window: Tauri 2 (Rust daemon, `rmcp` for MCP, `global-hotkey`, `trash`, `windows` crate for shell verbs) or .NET 8+ tray app hosting WebView2 (`ModelContextProtocol` NuGet, `NHotkey`, `IFileOperation` interop). Both are viable; Rust gives the MFT/USN crates and smallest idle footprint, .NET gives the easiest COM/shell interop. Electron is the weakest fit (RAM, no `MOD_NOREPEAT`, no built-in reveal flags). Code-sign the executable for AppLocker/WDAC.

**Query syntax (v1)**
- Space = AND of substring terms on file name; `"quoted phrase"` contiguous; `-term` NOT (`!term` alias); `ext:md,pdf`; `path:term` or any term containing `\`/`/` matches the full path; `*`/`?` wildcards; "substring" / "whole word" / "regex" match-mode toggle shown as a badge. No OR, size or date operators in syntax — those are chips/filters.
- Ranking: exact name > prefix > word-boundary > substring in name > path match; shorter name wins ties; frecency bonus (exponential decay, 30-day half-life) for files opened from the app; chips and sort buttons (Name/Ext/Date) override.

**Filters and saved searches**
- Chips: Docs (`doc docx odt rtf txt md`), Sheets (`xls xlsx csv ods`), PDF, Images (`png jpg jpeg gif webp svg avif heic bmp ico`), Code (highlight.js language extension list), Folders. Modified-date filter: Today / 7 days / 30 days / custom range (maps to Everything's `dm:` semantics). Saved searches = query string + chips + date + sort + name, stored in the daemon's settings file; expose them in the overlay too.

**Include/exclude**
- Roots per machine (include list); gitignore-style exclude patterns with `**/` semantics and "parent-excluded cannot be re-included" surfaced in the UI; attribute toggles (hidden/system) default on; default exclude list as in Q6; secrets deny-list (Q13) applied to results and previews for everything, not just MCP; a "what did this exclude" counter per rule so the user can tune.

**Preview**
- Markdown/Markmap/Mermaid: MD-Vault components. PDF: pdfjs-dist, bytes from the daemon, worker on the app origin. DOCX: docx-preview, mammoth fallback, DOMPurify. IPreviewHandler hosting (PowerToys Peek pattern) = later tier for Office fidelity.

**Actions**

## 10. Addendum, 2026-11-06 (later the same day): the pure-Python constraint

### 10.1 The constraint and what it rules out

The tech-lead relayed the reference build's README: "Requires Windows 10/11 and Python 3.10+ on PATH. No admin rights needed" and "Why Python and not an exe: many managed machines block unknown executables (AppLocker). A script run by an already-approved Python is allowed." It installs `pillow` + `pywin32` via a PowerShell script and adds a Startup-folder shortcut. (The transcription is now in the repo: `C:\AI Projects\Assistant\docs\reference\2026-11-06-assistant-popup-readme.md`, lines 28, 36 and 43–46; see section 12.) Treat "runs as `.py` under an approved Python, pip-only dependencies, no compiled exe of our own" as a hard constraint for the shipped app. Confidence that this is the right reading of AppLocker: High — Microsoft's AppLocker default executable rules allow Everyone only under `Windows` and `Program Files`, and Microsoft explicitly warns against path rules for "standard user writable locations" (https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/working-with-applocker-rules); an approved `python.exe` running a script is the standard way around that.

This removes from the shipped app: Tauri/Electron/.NET hosts; every Rust crate named in sections 3 and 7 (`usn-journal-rs`, `ntfs-reader`, `rmcp`, `trash`, `global-hotkey`); code-signing as a mitigation; `es.exe` and Everything itself on the work laptop (both are unknown executables there). Two nuances:

- **Compiled Python wheels (`.pyd`/bundled DLLs) are evidently allowed on the work laptop**, because the reference build already runs `pywin32` (ships `pywintypes*.dll`, `pythoncom*.dll`) and `pillow` (compiled imaging core). AppLocker's DLL rule collection is separate from the EXE collection and is commonly left off; the evidence here is the user's own working build, not a policy dump. Confidence: Medium (observation). Keep compiled wheels to the minimum anyway and flag each one below.
- **Node is not needed on the work laptop.** All browser-side preview libraries are static files; the Vite build of the MD-Vault components happens once on the personal laptop (MD-Vault already has a built `dist/` and `dist.tar` in `C:\AI Projects\MD-Vault\`) and the output is vendored into the Python package.

### 10.2 Indexing in Python without admin

- **Mechanism.** CPython's `os.scandir()` uses `FindFirstFile`/`FindNextFile` on Windows and caches the full stat result on each `DirEntry`: "does not require a system call on Windows (except for symlinks)"; PEP 471 reports `os.walk()` "about 8-9 times as fast on Windows" once built on scandir (https://peps.python.org/pep-0471/). So file size and modified time come free with the name — the same "attributes from the enumeration record" rule as the native design, and no `FindExInfoBasic`/`LARGE_FETCH` tuning is exposed (minor loss). Confidence: High.
- **Measured speed (closest data found).** scandir-rs benchmark on a 2014-era i7-4810MQ laptop with SSD, `C:\Windows` = 132,604 directories + 349,911 files (482 k entries): `os.walk` (Python 3.10) **21.8 s**, the Python `scantree` recipe 13.1 s, the compiled Rust walker 4.1 s; Linux kernel tree (70 k files) on the same Windows machine: `os.walk` 2.0 s (https://docs.rs/crate/scandir_rs/latest). That is roughly **45 µs per entry for pure-Python `os.walk`** on old hardware, likely a warm-ish cache. No million-entry Python benchmark on NTFS exists in anything fetched. Confidence: Medium (third-party benchmark, old hardware, cache state unstated).
- **Extrapolation for this project (`[inference]`, must be measured on both laptops before the PRD fixes numbers):** 0.3 M entries (the reference build's count after excludes) ≈ 10–15 s; 1 M ≈ 45–60 s; 2 M ≈ 90–150 s, all pure Python with a warm cache on a modern laptop; a cold cache adds the disk's directory-read time (minutes on the first run after boot). Ways to claw back time, in order of cheapness: (1) walk with `os.scandir` directly and apply exclude rules at directory level so excluded trees are never entered; (2) parallelise per top-level directory with threads — `os.scandir` releases the GIL around the Win32 calls `[inference from CPython practice, not verified this session]`; (3) persist the index and make full rescans rare (incremental rescan compares each directory's modified time, which `DirEntry.stat()` gives for free); (4) optional compiled accelerator `scandir-rs` (MIT OR Apache-2.0, PyO3 wheel, 43 stars, ~5x faster in its own benchmark; https://github.com/brmmm3/scandir-rs) — a compiled wheel, so flag it and keep the pure-Python path as the fallback.
- **Memory.** Python objects are heavy: a path string plus a tuple of size/mtime is several hundred bytes, so 2 M entries as plain objects could reach 0.5–1 GB `[inference]`. Use a compact layout: one lowercase names blob plus `array('I')`/`array('q')` offsets, sizes and timestamps, parent-directory indices instead of repeated path prefixes, and pickle/`sqlite3` on disk. The reference build's "0.3M entries, 42.3 ms" is consistent with `str.find` over a single joined lowercase string (C speed) and is the simplest query engine that meets the 50 ms target at 2 M `[inference]`.
- **Change watching.** `pywin32` exposes `win32file.ReadDirectoryChangesW(handle, size, bWatchSubtree, dwNotifyFilter, overlapped=None)` returning `(action, filename)` tuples for a synchronous call; the directory handle needs `FILE_LIST_DIRECTORY`; the overlapped form must be given a buffer or "can crash Python" (https://mhammond.github.io/pywin32/win32file__ReadDirectoryChangesW_meth.html). Overflow handling (`ERROR_NOTIFY_ENUM_DIR` → re-walk subtree) is the same as section Q1. Alternative: `watchdog` 7.1.0 (Apache-2.0, Python ≥ 3.11, released 2026-11-04) implements Windows via "ReadDirectoryChangesW with I/O completion ports", uses `ReadDirectoryChangesExW` on Windows 10 1709+, and added "double-buffering ... to avoid missed events under high load"; it publishes platform wheels (https://pypi.org/pypi/watchdog/json). One synchronous `pywin32` watcher thread per root with a 64 KB buffer is enough for v1; `watchdog` is the upgrade if event loss shows up. Confidence: High on APIs; Medium on which to choose.

### 10.3 MFT/USN from Python where admin exists

No maintained Python library reads a live volume's MFT or USN journal; the search returned only Microsoft's docs and a Go project (https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-mft_enum_data_v1, https://pkg.go.dev/github.com/chaugan/swinv/internal/usn). It is nevertheless ~200 lines of `ctypes`: `CreateFileW(r"\\.\C:", GENERIC_READ, FILE_SHARE_READ|FILE_SHARE_WRITE, ...)`, `DeviceIoControl(FSCTL_ENUM_USN_DATA, MFT_ENUM_DATA_V1, ...)` paged on `StartFileReferenceNumber`, parse `USN_RECORD_V2/V3` (file reference, parent reference, name), then `FSCTL_READ_USN_JOURNAL` for deltas. Parsing 1–2 M records in pure Python will take seconds, not the sub-second native figure `[inference]`, but still far below a cold crawl. It must run in an **elevated `python.exe`** — on the personal laptop a Task Scheduler job with "Run with highest privileges" launching `pythonw.exe helper.py`, writing to the shared index file or a local pipe; on the work laptop it is not available at all. Everything as an accelerator via `everyfile` (MIT, pure `ctypes` WM_COPYDATA, https://pypi.org/project/everyfile/) is pip-only, but requires `Everything.exe` running — fine on the personal laptop, blocked on the work laptop. Confidence: High on APIs; the effort estimate is mine.

### 10.4 MCP in Python

`mcp` 2.3.0 (MIT, Python ≥ 3.10) requires `starlette`, `uvicorn`, `pydantic ≥ 2.12`, `anyio`, `sse-starlette`, `jsonschema`, `pyjwt[crypto]`, `python-multipart`, `opentelemetry-api`, and `pywin32` on Windows (https://pypi.org/pypi/mcp/json) — all pip packages that run under `python.exe`; `uvicorn` is a Python module, not an executable, so AppLocker is not triggered. Streamable HTTP via `mcp.run("streamable-http")` or `streamable_http_app()` mounted in Starlette; DNS-rebinding protection is on by default (only `127.0.0.1`, `localhost`, `[::1]` Hosts accepted) (section Q13). The stdio shim for Claude Desktop is `python -m <pkg>.mcp_stdio` referenced directly from `claude_desktop_config.json` (`command: "python"`), so no `.mcpb` packaging is needed. Confidence: High.

### 10.5 HTTP server for the web UI

Because `mcp` already pulls in Starlette and uvicorn, the web UI and JSON API should be the same Starlette app: `StaticFiles` for the vendored build, JSON routes for search/preview/actions, `/mcp` mounted from the SDK, one process, one loopback port, one bearer token (also checked on the API routes; the browser UI receives it once via a launch URL). The stdlib alternative, `http.server.ThreadingHTTPServer`, is documented as "not recommended for production. It only implements basic security checks", defaults to HTTP/1.0 (no keep-alive unless `protocol_version = "HTTP/1.1"` and exact `Content-Length`), and `SimpleHTTPRequestHandler` follows symlinks (https://docs.python.org/3/library/http.server.html) — acceptable for the reference build, superseded here. Confidence: High.

### 10.6 Preview rendering stays in the browser

Unchanged from Q8 and strengthened: every preview library (pdf.js, docx-preview/mammoth, SheetJS CE, papaparse, highlight.js, react-markdown, mermaid, markmap, DOMPurify) runs in the browser from static files served by the Python daemon; Python only streams bytes (`Range` requests for large text, whole file for PDF/DOCX/XLSX with a size cap) and does binary sniffing, OneDrive-placeholder checks and the secrets filter. ### 10.7 Hotkey, popup window and startup in Python

- **Hotkey.** `pywin32` exposes `win32gui.RegisterHotKey(hWnd, id, Modifiers, vk)` (https://mhammond.github.io/pywin32/win32gui__RegisterHotKey_meth.html); `WM_HOTKEY` (0x0312) arrives on the registering thread's message queue, so the popup process needs a message loop — tkinter's main loop already pumps Windows messages, and a hidden `win32gui` window or a `ctypes` `user32.RegisterHotKey` + `PeekMessage` poll from `root.after()` both work. All the Q10 rules apply unchanged (system-wide uniqueness, no Win+*, `MOD_NOREPEAT`, UIPI). Avoid the `keyboard`/`pynput` packages: they install low-level hooks, which UIPI blocks for elevated foreground windows and which Windows silently removes if the callback is slow (section Q10). Confidence: High.
- **Popup.** Three pip-only options. (a) **tkinter** (stdlib; the reference popup evidently used tkinter + pillow): fastest to show, enough for the compact FILES-mode list, cannot render the Markdown/PDF previews. (b) **Edge in app mode** — `msedge.exe --app=http://127.0.0.1:<port>/?token=...` gives a chrome-less window of the full web UI using an already-approved executable; good for "Full page (F11)" and for the preview pane. (c) **pywebview** 6.2.1 (BSD-3-Clause, Python ≥ 3.8) embeds the WebView2 runtime in a Python-owned window via `pythonnet`, which "requires > .NET 4.0" (https://pypi.org/pypi/pywebview/json, https://pywebview.flowrl.com/guide/installation.html); pip-only, but it loads .NET assemblies through `pythonnet`, so verify once on the work laptop before depending on it. Recommendation: (a) for the hotkey popup, (b) for the full UI, (c) only if the user wants previews inside the popup itself. Confidence: High on facts; the recommendation is mine.
- **Startup.** Startup-folder shortcut to `pythonw.exe <daemon>.py` (as the reference build does) — no admin, no service, no scheduled task required; the elevated USN helper of 10.3 is the one optional scheduled task, personal laptop only.

### 10.8 Shell actions in Python

- Reveal: `win32comext.shell.shell.SHOpenFolderAndSelectItems(Folder, Items, Flags=0)` exists in pywin32 (https://mhammond.github.io/pywin32/shell__SHOpenFolderAndSelectItems_meth.html), with PIDLs from `shell.SHParseDisplayName`; `pythoncom.CoInitialize()` first. Same MAX_PATH and `\\?\` caveats as Q9.

- Recycle Bin: `send2trash` 2.1.0 (BSD-3-Clause, released 2026-01-14) uses `IFileOperation` when installed as `send2trash[nativeLib]` (pulls `pywin32 ≥ 305`) and falls back to `SHFileOperation` otherwise (https://pypi.org/pypi/Send2Trash/json). Whether it sets `FOF_WANTNUKEWARNING` was not verified this session; if not, call `shell.SHFileOperation` directly with `FOF_ALLOWUNDO | FOF_WANTNUKEWARNING | FOF_NOCONFIRMATION` and check `fAnyOperationsAborted`, and in any case refuse deletes on `GetDriveType` = remote/removable to keep "never permanent" true.
- Rename: `os.rename` (kernel `MoveFileEx`, no Explorer notification) is the simple path; `IFileOperation::RenameItem` through pywin32's COM support is possible but unverified this session — the name-validation rules from Q11 apply either way.
- Clipboard: `win32clipboard` or tkinter's `clipboard_append`.
Confidence: High for the pywin32 entry points fetched; Medium for the two "not verified" items.

### 10.9 "Ask notes" (BM25 over Markdown) and the reference build's split

### 12.2 What this changes

1. **Query-syntax conflict.** Section 7 proposed `-term` as NOT (Google style). The reference build uses `-e yml` and `-p Documents` as *flags*, so `-term` NOT would silently break the user's habit (`config -e yml` would become "config AND NOT e AND yml"). Options for the PRD: (a) keep `-e`/`-p` for compatibility and use Everything's `!term` for NOT; or (b) drop the flags in favour of `ext:`/`path:` and keep `-term`, accepting a retraining cost; or (c) support both with a disambiguation rule (`-e`/`-p` followed by a value are flags, any other `-word` is NOT) — simplest for the user but the most surprising edge cases. I recommend (c) with the badge/help text showing the parse, or (a) if the product role prefers one unambiguous grammar.
2. **Bare-extension tokens as filters.** `design md` treating `md` as an extension filter conflicts with pure substring semantics (it would otherwise also match `md-notes.txt`). The reference build's behaviour is the one the user chose; recommend keeping it: a bare token that equals a known extension *and* is not the only token is treated as `ext:` unless quoted. Show the interpretation in the results header ("ext: md").
3. **Path narrowing by extra token.** `design doc` "narrows by path" means secondary tokens are matched against the full path, not only the name. This is compatible with the ranking in Q5 (name matches rank above path matches) and should be the default rather than requiring `path:`.
4. **Two MCP servers or one.** The popup already has an MCP server for cards/reminders. The file-search MCP (section Q13/11) can be a second server (`assistant-search`) or a merged `assistant` server exposing both tool groups. Product decision; technical note: one daemon, one port, one token is simpler for Claude Code/Desktop configuration, but the overlay brief owns the cards server, so a merge means one owner for both.
5. **Token file pattern.** The reference's `token.txt` next to the app matches the bearer-token-on-localhost design in Q13; keep the file user-only (`%LOCALAPPDATA%` or `~/.assistant/`) rather than next to the code.
6. **Architecture confirmation.** The README confirms the popup → fastsearch split (popup calls a separate tool with its own saved index) and the "index from <date>" freshness indicator; section 11's two-process design (daemon + popup over localhost HTTP) replaces the script-invocation coupling and lets the browser UI and MCP share the same index.
7. **"Ask notes" is explicitly local-only** ("nothing leaves your PC") — a product promise to keep; it also means the BM25 mode and the "Ask Claude about this file" action must be visibly different in the UI so the user never confuses a local search with a cloud call.
