# Research brief: product name availability check (rename of "Assistant")

- Date: 2026-11-07
- Author: researcher (TeamAgents)
- Status: first version. Append-only from here (archaeology rule): new findings go in dated sections at the end.
- Hand-off: tech-lead (the user picks; `product` then records the decision in the PRD; the rename itself is an engineering task — package name, CLI entry point, `ASSISTANT_HOME` / `~/.<name>` default, README).

## Question

The app currently called "Assistant" — a free, open-source, pure-Python Windows desktop app made of (1) an always-on-top alert overlay (stacked cards for "Claude Code needs you", meetings, reminders, fed by Claude Code hooks, an MCP server and a CLI) and (2) an Everything-like instant file-name search with a hotkey popup, a full-page web UI with previews (markdown/markmap/mermaid, docx, pdf, xlsx), "Ask Claude about this file" and a plugin system — needs a name that is not already used as software. The name becomes the GitHub repo, probably the PyPI package, the command people type (for example `beacon`) and the settings folder `~/.<name>`.

"Is this name free?" decomposes into: is the PyPI name free; is the npm name free (future web-UI package, and because npm squatting is how most collisions surface); does a GitHub repo or org with the exact name have real usage; does any desktop app, launcher, search tool, notification/reminder tool, developer tool or AI assistant use it; is it in the Microsoft Store or winget; is there a live US (class 9 / 42) or EU trademark on it; and is the .com/.app domain live. A name is **CLEAR** only when PyPI, npm and GitHub exact-name checks are empty or trivially unrelated and no related software or software trademark turned up. **MINOR** = small unrelated or dead uses only. **TAKEN** = software in a related space, a package or repo with real usage, or a live software-class mark.

## Method

- No `deep-research` skill exists in `C:\AI Projects\TeamAgents\.claude\skills\` (same finding as the 2026-11-06 briefs), so this was a structured fan-out: seven read-only research subagents each took a batch of 6–10 names and ran the identical protocol below on 2026-11-07. The researcher then re-fetched the PyPI and npm registry endpoints for the five shortlisted names and ran independent web searches on the top three, and fetched `pypi.org/pypi/scout/json` as a positive control (it returned `scout 4.0.0`, released 2026-04-14), proving the 404s are genuine absences rather than a blanket fetch failure.
- Per-name protocol: PyPI JSON API `https://pypi.org/pypi/<name>/json` (the HTML project pages served a bot challenge to every batch, so the JSON API — equally authoritative — was used instead); npm registry `https://registry.npmjs.org/<name>` plus `https://api.npmjs.org/downloads/point/last-week/<name>` where a package existed; GitHub via `gh search repos <name> --match name --sort stars` and `gh api users/<name>` (gh 2.86.0, authenticated; two batches hit the search-API rate limit once and re-ran successfully); `winget.exe search "<name>"` (read-only; winget printed a harmless "Failed in attempting to update the source" warning once); WebSearch "<name> app" and "<name> software"; trademark lookup; `.com` and `.app` domain fetches.
- **Trademark checks are the weak point of this brief.** `trademarks.justia.com/search` returned HTTP 403 to every one of the ~60 queries (WebFetch and curl alike), and `tmsearch.uspto.gov` is a JavaScript application that cannot be queried by fetch, so it was not attempted. All trademark statements below come from web-search snippets of third-party USPTO aggregators (markinton.com, trademarkdir.com, gleanmark.com, trademarkelite.com, Justia detail pages that happened to be indexed). Those lag the register and can be wrong about status. EUIPO was not queried at all; one UK IPO journal entry surfaced via search (Vigilo, Vedette). A human should run the final candidate through USPTO TESS/TSDR and EUIPO eSearch before the rename ships. Subagents were told not to bypass bot checks with spoofed user agents and did not.
- Domain results: a fetch that fails (DNS NXDOMAIN, connection refused, TLS error) is recorded as **unknown**, not "available". Several `.com` hits served the identical 114-byte GoDaddy/Afternic "/lander" page, which means parked / for sale.
- Source classes used below: **[registry]** PyPI/npm JSON (authoritative for name availability), **[repo]** GitHub API counts, **[store]** winget/Microsoft Store, **[vendor]** a product's own site or app-store listing, **[aggregator]** third-party trademark snippets (indicative only), **[search]** absence in two web searches (negative evidence, not proof).
- Adversarial pass: the brief looked just as hard for reasons a name is bad (dead-but-squatting packages, 0-star repos created this month in the same niche, pending marks one letter away, sound-alikes of large brands) as for reasons it is good; the "Key conflict" column records the worst thing found, not the average.

## Risks / unknowns

1. **No official trademark register was queried.** Justia returned 403 throughout, tmsearch.uspto.gov is not fetchable, EUIPO was not attempted. "No mark found" for the shortlist means "no aggregator snippet surfaced in web search", which is negative evidence of moderate strength only. The final pick needs a human TESS/TSDR and EUIPO eSearch pass (ten minutes) before the rename is committed.
2. **Domain status is inferred, not confirmed.** NXDOMAIN or connection failures were recorded as unknown; no WHOIS was run. Only the .com/.app pairs were probed; .dev was not.
3. **Freshness.** Three collisions found in this brief were created within the last six weeks. A CLEAR verdict is a snapshot dated 2026-11-07.
4. **Store coverage.** winget covers the Microsoft Store and the community manifest only; Apple App Store and Google Play were covered by web search, not by direct store queries, so small mobile apps with the shortlist names could have been missed.
5. **Aggregator accuracy.** Markinton / trademarkdir / gleanmark class and status fields are known to lag; two aggregators disagreed on the status of one NUDGE registration, which illustrates the error bar.

### Spelling and pronunciation for English speakers (researcher judgment, unsourced)

- **Rakhsh** — one syllable, 6 letters, the `khsh` cluster is the only hurdle; English speakers will say "raksh" or "rocksh", which is fine and still unique. People will type `raksh` by mistake, and that misspelling is free on PyPI and npm (fetched 2026-11-07), so it can be registered as a redirect/alias at near-zero cost. Works as a CLI command and folder (`rakhsh`, `~/.rakhsh`).
- **Gordafarid** — 10 letters, four syllables, but every letter is pronounced as written ("gor-da-fa-REED"), so it is spellable after hearing it once. Long for a daily CLI command; a short alias would be needed (`gord` collides with a discontinued Discord client, gord-project/gord; `gfd` is uncommitted).
- **Pashutan** — 8 letters, three syllables, fully phonetic ("pa-SHOO-tan"); the easiest of the clear names to say and type. The variant spelling Peshotan belongs to an active developer on GitHub, so stick to Pashutan.
- **Manijeh / Tahmineh / Esfandiyar** — the `j`/`zh` and `eh` endings and the multiple transliterations (Manizheh, Tahmina, Esfandiar) mean people will spell them several ways; each is a woman's or man's given name first and a product second.
- **Zal / Giv** — trivially easy, which is exactly why both already collide (a 90-star Windows utility; a PyPI CLI and a live mark).
- **Sorush / Derafsh / Simorgh / Jam-e Jam** — the best meaning fits in the whole set, and each is either taken or awkward in English (`gh`, `fsh`, hyphenated slug).

### Abbreviations and backronyms

None reads naturally, so none is recommended. Specifically: **ZAL** as three letters inherits the hedihadi/zal and ZAL-Hamburg collisions whatever it is expanded to (a backronym such as "Zero-delay Alert Layer" does not change the string that is searched, installed or trademarked). **GIV** is blocked by the PyPI package `giv` regardless of expansion. **RAKHSH** in capitals reads as an acronym nobody can expand and loses the horse; use it as a word. The only abbreviation worth claiming is defensive: register `raksh` alongside `rakhsh` on PyPI so the common misspelling resolves to the same project.

### Ranked top 3

1. **Rakhsh** — the one name in the set that is both CLEAR on every registry and store and carries both halves of the product in its story (the fast horse that wakes the hero to warn him), with the only costs being the `khsh` spelling and the dormant GitHub handle.
2. **Gordafarid** — spotless (no software, brand, mark or live domain; an 8-star unrelated Go repo is the worst hit) with a credible "guardian at the gate" alert meaning, but ten letters long and English-unfamiliar, so it needs a short CLI alias.
3. **Pashutan** — the cleanest string of all (nothing found under any check, both domains unresolved) and the easiest to pronounce, but the meaning fit ("the immortal counsellor who is always there") is a stretch that will need a sentence of README to explain.

Honourable mention: **Zal** has a good alert meaning and is three letters, but a 90-star open-source Windows utility already carries the name on GitHub, Product Hunt and the App Store, and two live class-9 marks sit one letter away (ZAAL, ZAL-POP); it is usable only if the user accepts sharing the word with another Windows desktop tool.

### Risks / unknowns (this section)

1. **Trademark screen is aggregator-only**, as in the main brief: markinton and trademarkdir did not even resolve from two sandboxes, so several entries rest on search snippets, docketalarm and Justia detail pages. "No RAKHSH / GORDAFARID / PASHUTAN mark found" is negative evidence of moderate strength. Before committing, a human should run the chosen name through USPTO TESS/TSDR and EUIPO eSearch; ten minutes.
2. **Family-of-names effect.** Rakhsh (Rostam's horse) and Zal (Rostam's father) will read as sub-projects of the user's existing Rostam project to anyone who knows the poem. That is a free narrative if the two tools are meant to sit together, and a confusion if they are unrelated; the user should decide which.
3. **Persian-audience discoverability.** Every Shahnameh name is a common given name, a brand, or both in Iran (House of Bijan, Jam-e Jam TV, Soroush messenger, the Zarin "Faramarz" platform, rudabeh.app). Search results for the product will be dominated by the epic and by people for a long time. Gordafarid and Pashutan are the two exceptions whose search results are currently almost empty.
4. **Domain status inferred, not confirmed.** rakhsh.com resolves to Cloudflare but serves an origin error (registered, content unknown); rakhsh.app, pashutan.com/.app and gordafarid.app returned no DNS record, which is not proof of availability. No WHOIS was run.
5. **Freshness.** Two Derafsh repos and the `esfandiyar-site` repo were updated or created on 2026-11-07 itself. A CLEAR verdict is a snapshot of today; claim the PyPI and GitHub names the day a name is chosen.

### Recommendation (this section)

Pick **Rakhsh** if the user wants a Shahnameh name: it is clear on PyPI, npm, winget, Chocolatey and web search as of 2026-11-07, the misspelling `raksh` is also free, and the story (fast, loyal, wakes the hero to warn him) covers both the alert and search halves. Fall back to **Gordafarid** or **Pashutan** if the `khsh` spelling or the implied tie to the Rostam project is unwanted; both are spotless on every check but need a README sentence to justify the meaning, and Gordafarid needs a short CLI alias. Drop Simorgh, Jam, Giv, Siavash and Sorush (live class-9 marks and/or active packages or products), and treat Zal, Kaveh, Faramarz and Derafsh as usable only with eyes open.
